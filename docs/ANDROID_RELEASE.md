# Android Release Handoff — Project Two

Everything needed to take the app from this repository to an installable
Android build. Commands marked (blocked here) could not be run in this
environment — they require EAS authentication.

## Workflow: Continuous Native Generation (CNG)

The `android/` directory is **not tracked** in git (adopted in `e9ab64f`;
expo-doctor 21/21). `app.json` and the config plugins are the single source
of native truth; EAS regenerates native config from them at build time
(EAS uploads follow `.gitignore` when no `.easignore` exists). Never
recommit generated native source. To build locally, regenerate first:

```bash
npx expo prebuild -p android   # regenerates android/ from app.json
```

## What is already configured

- **Adaptive icon**: foreground + monochrome layers from the 1024px app icon,
  midnight-navy `#151D32` background (matches the Moonlit Garden theme).
- **Splash**: icon at 180pt width on `#151D32`, with an explicit dark variant
  on `#0E1526` so the launch screen never flashes white in dark mode.
- **Deep links**: `projecttwo://` custom scheme — the verified path used by
  password recovery (`projecttwo://reset-password`). The previously declared
  `https://projecttwo.app` App Links filter was **removed** after the domain
  proved not to exist (NXDOMAIN; see `docs/EXTERNAL_BLOCKERS.md`).
- **Permissions**: only `POST_NOTIFICATIONS`. No location, camera, contacts,
  or storage permissions are requested — the app is deliberately minimal.
- **EAS profiles** (`eas.json`): `preview` builds an APK (`environment:
  "preview"`), `production` builds an App Bundle (`environment:
  "production"`). Both read `EXPO_PUBLIC_SUPABASE_URL` /
  `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` from **EAS environment variables**
  — never from committed files.

## Secrets: use EAS environment variables (current tooling)

The deprecated `eas secret:create` flow is superseded by EAS environments,
which `eas.json` already targets (`"environment": "preview" / "production"`).
After `npx eas-cli login`:

```bash
npx eas env:create --name EXPO_PUBLIC_SUPABASE_URL \
  --value https://<ref>.supabase.co --environment preview
npx eas env:create --name EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY \
  --value <anon-key> --environment preview
# repeat with --environment production for the production profile
npx eas env:list --environment preview   # verify
```

Only the **anon/publishable** key may be embedded in the client. The
service-role key must never be added to any EAS environment.

## Build an installable APK (blocked here — needs `eas login`)

```bash
npx eas build -p android --profile preview
```

Produces a directly-installable APK at the URL EAS prints when finished.
For the Play Store:

```bash
npx eas build -p android --profile production
npx eas submit -p android --latest   # after configuring service account
```

## Compile locally instead (no EAS account needed — disk warning)

Local gradle builds need ~3 GB of downloads + intermediates **on top of**
SDK tooling. C: dropped to 103 MB during a previous attempt and the build
was aborted; **do not start one with less than ~5 GB free**.

```bash
npx expo prebuild -p android   # regenerates android/ from app.json
cd android && ./gradlew assembleRelease
```

Requires Android SDK 36 (Android 16) tooling: `ANDROID_HOME` set, SDK
Platform 36 + Build-Tools 36 installed via Android Studio's SDK Manager.
Expo SDK 57 targets API 36 per Google Play's current requirement. The
release variant signs with the debug keystore generated by prebuild
(`android/app/debug.keystore`) — replace with real signing credentials
before any public distribution.

## Post-build checklist (manual, on-device)

1. Install the APK → sign up with a real email → confirm via inbox → sign in.
2. Second device (or second account): join via the 6-character invite code.
3. Both answer today's letter → envelope opens → both answers visible.
4. Switch Android language/system dark mode → splash and theme stay coherent.
5. Kill the app cold → reopen → session persists (no forced re-login).
6. Airplane mode → open app → friendly backend notice with working retry
   (never a silent demo-mode fallback).
7. Weekly adventure: both partners complete their side → "Done together".
8. Deep link: open `projecttwo://reset-password` from a recovery email →
   the reset screen opens (custom scheme, no domain dependency).
